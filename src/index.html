Quick start

  1. Stack — start the Ollama Compose stack.
  2. Secrets — store API tokens (e.g. github_token).
  3. Workers — configure tasks and start containers.

Without explicit mappings, GITHUB_TOKEN is passed to agents when github_token (or a legacy saved token) exists.

Ollama stack (Docker Compose)

Compose files are bundled in the app, written to your app data folder, then docker compose is run. GPU mode adds ollama-compose.gpu.yml (gpus: all). Requires Docker Desktop.

                suggested key name cursor_api_key.

Worker domain

        

          

            The domain selects which rules and system-prompt guidelines the agent uses (from the
            bundled rules tree). It is not a Docker image name or a URL.
          

          

            git — Git / GitHub maintenance: pull request limits, branch safety, repository
            allowlists, and audit logging for mutations. Use this when the worker should drive
            git/gh against repos you trust.
          

          

            market — Reserved in the rules tree for future monitoring-style work. It is
            marked inactive until you extend that domain in the product.
          

          

            Other (custom key) — Only use if you have added a matching domain entry to the
            rules tree; otherwise validation or prompts may not match what you expect.
          

        

      

    


    

      

        
        
Tasks: cadence and one-shot

        

          

            Tasks are instructions the agent loop (inside the container) considers on a timer. The
            loop wakes every pollSeconds (often 45s), builds a short list of due tasks, and
            sends one chat request to Ollama with that list plus your context.
          

          

            Cadence (repeating) — Runs again after each interval you set (in
            seconds). The loop uses UTC time buckets, so a 3600s cadence is roughly hourly. Good for
            ongoing maintenance sweeps.
          

          

            One-shot — Included in a run once; after a successful cycle it is marked done in
            persisted state and skipped later. Good for a finite checklist item.
          

          

            Why both? You might want a periodic sweep (cadence) plus several one-time setup items
            (multiple one-shots). Multiple one-shots are normal when each line item should complete independently.
